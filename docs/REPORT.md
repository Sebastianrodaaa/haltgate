# haltgate v1 report

Small-scale toy run on CPU. All task data is generated (SYNTH). Every number below is read from `results/*.json`,
written by `python3 -m haltgate.run`; the results table between the markers is regenerated by `scripts/plots.py`.

## Question

A looped transformer applies one shared block N times. N is normally fixed at train or serve time. Can a typed
System One decision model, reading cheap features after each loop and choosing from {continue, halt, escalate},
spend fewer loops than Nmax while a Learn-then-Test (LTT) calibration keeps the false-halt rate on items that still
improve at most alpha with probability at least 1 - delta?

## Method

**Backbone.** `haltgate/model.py`. Token + learned position embedding `e`, a shared block of 2 pre-LN transformer
layers (d=128, 4 heads, 0.41M params), applied `Nmax = 8` times with input injection: `h_i = block(h_{i-1} + e)`,
`h_0 = 0`. One shared LayerNorm + linear readout after every loop. Bidirectional attention; answers are predicted at
`?` slot positions at the end of the input. Trained from scratch, 3000 AdamW steps, batch 128, lr 1e-3 one-cycle,
loss = mean cross-entropy over all 8 loop readouts (deep supervision). One backbone per seed (0, 1, 2), frozen after
training; only the gate is fit and calibrated.

**Tasks (SYNTH, `haltgate/data.py`).** Uniform mixture of
- parity: L in [2, 16] random bits, left-padded with zeros to width 16, answer is the parity bit;
- addition: two numbers with 1 to 10 digits, zero-padded to 10 digits, least-significant digit first, 11 answer digits;
- copy-with-noise: a 3 to 8 digit string shown as 3 copies, each digit replaced by a noise token with p=0.3
  (every position survives in at least one copy); answer is the clean string.

Accuracy is exact match over all answer slots.

**Oracle labels.** Every item is run to Nmax offline. With `c_i` = correct at loop i, the label at loop i is
`continue` if `c_i = 0` and some `c_j = 1` for `j > i` (the item still improves), `escalate` if the item is never
correct within Nmax, and `halt` otherwise. The hard set S is the items that still improve at some loop. A false halt
is stopping an item at a loop where it still improves.

**Features (`haltgate/features.py`).** After loop i: mean-pool of `h_i` over non-pad tokens (128), mean and max
entropy of the slot readouts, min slot confidence, loop index / Nmax, relative delta-norm `|h_i - h_{i-1}| / |h_{i-1}|`,
and the fraction of slot predictions that flipped since loop i-1. Nothing uses labels; slot positions are visible in
the input.

**Decision model (`haltgate/dm.py`).** Multinomial logistic regression (class-balanced, L2 1e-3, LBFGS) on
standardized features, fit on a gate-train split. Output is a point on the 3-simplex. The typed decision at loop i is
`stop` when `P(halt) + P(escalate) >= lambda`; the stop type is whichever of halt/escalate is likelier. In v1,
`escalate` stops the loop and flags the item (the deeper path is not configured; see Limitations). Loop Nmax always
stops.

**LTT (`haltgate/ltt.py`).** On the calib split restricted to S, for lambda from 1.0 down to 0.0 in steps of 0.01,
compute the number of false halts `k` and the binomial p-value `P(Binom(|S|, alpha) <= k)` for `H0: risk > alpha`.
Fixed-sequence testing: walk lambda from conservative to aggressive and stop at the first p > delta; lambda* is the
last rejected value. If even lambda = 1.0 (never stop early) is not rejected, LTT returns no configuration and the
gate runs Nmax. alpha = 0.05, delta = 0.1.

**Splits.** Per seed, three fresh generated splits of 1000 items per task: gate-train (fit DM), calib (LTT and
baseline tuning), test (all reported numbers).

**Arms.**
- fixed-N for N in 1..8 (the brief asks for {1, 2, 4, Nmax}; all eight are kept);
- `fixed-interp`: fixed-N at the gate's fractional mean loops (floor or ceil at random in the right ratio, expected accuracy);
- `entropy-matched`: halt when max slot entropy <= tau, tau tuned on calib so its calib mean loops matches haltgate's;
- `entropy-ltt`: the same LTT procedure applied to the raw entropy score (isolates what the DM adds);
- `random-matched`: haltgate's own halt loops randomly permuted across test items (20 shuffles, expected accuracy);
- `haltgate`: DM + LTT.

**Hypothesis and failure criteria (from the brief).** (1) Test false-halt rate on S stays within alpha.
(2) At matched mean loops, accuracy is >= 5 points above fixed-N at that mean and >= 3 points above entropy early
exit tuned on the same calib split. It fails if the bound is violated, if the 95% bootstrap CI on the gap vs the
better baseline includes 0, or if some fixed N <= haltgate's mean loops already matches its accuracy.

**Wall clock.** The gate is also run online (`haltgate.run.gated`): each loop runs only on items still alive, then
features and DM scores are computed for those items. Reported as ms/item at batch 512 on the CPU threads used, best
of 3. The online halts are checked against the offline simulation.

## Related work

- How to Loop Your Transformer (arXiv 2610.40325) studies which blocks to loop, how often and how state passes;
  N is fixed. haltgate keeps the loop design fixed and gates N per item.
- Spherical Fixed-Point Reasoners (arXiv 2610.25646) halt loops with a geometric criterion on the hypersphere; no
  typed decision model and no finite-sample false-halt bound.
- Truncate or Not? (2610.26030) and One Model, Two Paths (2610.33517) are about training looped models and balancing
  single-pass vs looped quality, not runtime gates.
- Decision Models as Policy Gates (2611.02155) gates tool calls with typed classifiers; haltgate applies the same
  shape to loop iterations.
- ACT (Graves 2016), Universal Transformers (Dehghani et al. 2018) and PonderNet (Banino et al. 2021) learn halting
  jointly with the model; haltgate is post hoc on a frozen backbone, with a calibrated bound.
- CALM (Schuster et al. 2022) calibrates early exit on ordinary layer stacks with LTT-style risk control on
  output consistency; haltgate controls the false-halt rate on items that still improve, on a shared-block loop.
- Mixture-of-Depths (Raposo et al. 2024) routes tokens around layers; haltgate routes whole items across loops.
- Learn then Test (Angelopoulos et al. 2021) supplies the calibration.

(The 2610/2611 arXiv IDs are as listed in the project brief.)

### Discussion

The pre-registered verdict is **FAIL**. None of the three failure criteria fired, but two of the three
hypothesis parts were not met.

What held:

- **The bound.** Test false-halt rate on S was 1.8%, 3.8% and 4.8% for seeds 0, 1, 2 (alpha = 5%). LTT picked
  lambda* = 0.88, 0.90, 0.68. Seed 2 sits close to the bound; that is what a calibrated bound looks like.
- **Compute.** The gate used 2.32 mean loops out of 8 (71% of loops skipped), pooled accuracy 90.6% vs 90.8% for
  fixed-8. On seed 0, wall clock was 0.41 ms/item vs 1.34 ms for fixed-8 (8 threads, batch inference; timings are
  noisy at this scale).
- **Ordering.** At matched loops the gate beats fixed-N interpolation (+1.6 pts), entropy early-exit (+1.2 pts) and
  random halting (+3.4 pts), all with bootstrap CIs excluding 0. Entropy early-exit calibrated with the same LTT
  procedure reached 90.2% at 2.54 loops: close, but more loops and lower accuracy.

What failed:

- **Effect size.** The brief asked for >= 5 pts over fixed-N and >= 3 pts over entropy at matched loops. On this
  suite that was not reachable by any gate. The headroom is the gap between fixed-8 (90.8%) and fixed-N
  interpolated at 2.32 loops (about 89.2%): roughly 1.6 pts. The gate recovered essentially all of it. The
  backbone solves addition and copy in one or two loops and plateaus on parity (about 65-76% at Nmax), so only
  13-15% of test items are in S at all.

The honest reading: on these toy tasks the typed gate does what it is calibrated to do and is the best arm on the
accuracy/compute frontier, but the tasks do not reward extra loops enough for a 5-point gap to exist. A fair
retest needs a backbone whose accuracy keeps climbing with loops (harder parity curriculum, longer training, larger
Nmax), so that fixed-N at the gate's mean loops is well below fixed-Nmax.

## Limitations

- Toy scale: 0.41M-parameter backbone, three generated tasks, 3 seeds, 3000 training steps on CPU. Nothing here
  says how the gate behaves on a pretrained looped LM.
- `escalate` only stops and flags. A configured deeper path (larger N budget or a non-looped model) is not built in
  v1, so escalation is measured (rate, precision) but buys no accuracy.
- The LTT guarantee is marginal over calib draws and conditional on exchangeability of calib and test items; it is
  a guarantee about the false-halt rate on S, not about accuracy.
- Oracle labels use exact match with eps = 0 (no margin-based improvement), and are only defined up to Nmax.
- The optional swap to a frozen open decision-model scorer (brief step 5) was skipped: no CPU-sized DM stand-in was
  available offline, and logistic regression is the honest small baseline.
